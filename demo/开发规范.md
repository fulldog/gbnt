## 1. 文档边界

**本文档只收通用工程规范，禁止任何业务线规则混入。**

以下内容属于业务线规则，写入各项目文档（项目说明、PRD、`AGENTS.md` 等），**不得**写入本文档：

| 禁止写入本文档                   | 示例             |
| -------------------------------- | ---------------- |
| 项目背景 / 业务定位 / 客户名称   | —               |
| 具体菜单、页面、功能点描述       | —               |
| 业务表名、字段名、接口路径与参数 | —               |
| 品牌主色、Logo、项目专属视觉资源 | `#xxx`、品牌图 |
| 演示数据、测试用例、样例路径     | —               |
| 业务流程、决策规则、计算公式     | —               |

**Agent 自查**：新增内容前先对照上表。属于业务线的一律不进本文档；发现误入的业务内容，应主动提出并移除。

各项目直接引用本规范，**不必再写一份项目级「开发规范」**。确需记录的例外（如某次获准的外链），写入该项目的 `AGENTS.md` 或项目说明，并在引用处注释原因。

## 2. 技术栈与定位

### 2.1 先定技术栈（必问）

新建项目、或 Agent 首次进入项目时，**必须先向用户确认技术栈**，并写入该项目 `AGENTS.md` 顶部（示例：`技术栈：栈 B（localStorage）`）。未确认前，不得擅自搭建后端或假定有 SQLite。

可选两档（可按项目约定扩展，但新增档位须在 `AGENTS.md` 写清适用章节）：

| 档位                     | 组成                                                                     | 典型场景                                     |
| ------------------------ | ------------------------------------------------------------------------ | -------------------------------------------- |
| **栈 A · 全栈**   | 原生 HTML + CSS + JS +**FastAPI** + **SQLite**（SQLAlchemy） | 需要服务端、持久库、多端共享数据、瓦片代理等 |
| **栈 B · 纯前端** | 原生 HTML + CSS + JS +**localStorage**（无后端）                   | 单机演示、表单/配置落本地、同事只交付静态页  |

两档**共用**：前端三件套、目录与命名中的前端部分、UI 硬性约束、协作约定、Git 基本要求。

### 2.2 章节适用一览

| 章节                                       | 栈 A                      | 栈 B                                |
| ------------------------------------------ | ------------------------- | ----------------------------------- |
| §3–§6 前端部分（骨架、模板、UI 约束等） | ✅                        | ✅                                  |
| §6.4`config.js` / `?api=`             | ✅                        | ❌ 跳过                             |
| §6.5 localStorage 约定                    | ❌ 一般不用               | ✅                                  |
| §7 后端与 API（含响应码、库表变更）       | ✅                        | ❌**整章跳过**                |
| §8 地图与图表                             | ✅；瓦片须走后端缓存      | ✅ 图表照常；地图见 §8.1 栈 B 说明 |
| §9 本地启动                               | ✅ 前后端一键启动         | ✅ 仅静态服务（见 §9.3）           |
| §10 Git 与交付                            | ✅ 含 backend /`.db` 等 | ✅ 精简忽略项（见 §10）            |
| §11 协作约定                              | ✅                        | ✅                                  |

**栈 B 明确不必遵循**：FastAPI / uvicorn / SQLite / SQLAlchemy、`backend/` 目录、`§7` 全部、`API_BASE_URL` 与 `?api=`、后端瓦片代理与 `tile-cache`、启动脚本里的 venv / 后端端口逻辑。

### 2.3 共用选型

| 项           | 选型                                                                           |
| ------------ | ------------------------------------------------------------------------------ |
| 前端         | 原生 HTML + CSS + JavaScript（无构建，Live Server / 静态服务直接打开）         |
| 本地预览     | VS Code / Cursor Live Server，或一键脚本内的 HTTP Server（前端默认从 5501 起） |
| 地图（按需） | MapLibre GL（本地化；叠加层推荐 deck.gl）                                      |
| 图表（按需） | ECharts（本地化，禁止 CDN）                                                    |

**仅栈 A**：

| 项       | 选型                                                                 |
| -------- | -------------------------------------------------------------------- |
| 后端     | FastAPI                                                              |
| 数据库   | SQLite（SQLAlchemy）                                                 |
| API 服务 | uvicorn（默认`http://127.0.0.1:8000`，实际端口由启动脚本动态分配） |

**仅栈 B**：

| 项         | 选型                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 数据持久化 | `localStorage`（经 `frontend/js/storage.js` 统一读写，见 §6.5） |
| 后端       | 无                                                                   |

**交付约定**（两档共用）：

- 本地开发保留完整 Admin 骨架（侧栏 / 顶栏 / 内容区），便于联调预览。
- 正式交付按宿主平台要求裁剪（如只交付内容区域）。
- 栈 A 为前后端分离；栈 B 为纯静态前端。

## 3. 目录结构

### 3.1 共用（栈 A / 栈 B）

单端项目可仅保留一个业务入口 HTML。**Web + 小程序（或 App H5）双端**时，根目录只放选端页，两端页面分目录，与公共资产平级：

```text
/
├── index.html                    # 选端页（双端项目唯一允许的 index.html）
├── web/                          # Web 管理端：各自 HTML
│   ├── login.html
│   └── …
├── miniapp/                      # 小程序端 / 手机壳 H5：各自 HTML
│   ├── login.html
│   └── …
├── frontend/                     # 公共资产（与 web、miniapp 平级）
│   ├── assets/
│   ├── css/
│   │   ├── variables.css
│   │   ├── layout.css
│   │   └── pages/
│   ├── partials/
│   ├── libs/
│   └── js/
│       ├── logger.js
│       ├── icons.js
│       ├── config.js
│       ├── nav.js
│       ├── layout.js
│       └── pages/
├── AGENTS.md
├── 开发规范.md
├── .gitignore
├── 启动.command / 启动.bat
└── .logs/
```

仅单端、无选端需求时，可将入口 HTML 直接放在根目录（如 `app.html`），**仍禁止**把业务页随意堆满根目录；多页应收入对应端目录或 `frontend/pages/`。

> **关于 `index.html`**：双端选端页固定用根目录 `index.html`（双击 / 一键启动打开）。其它业务页仍禁止命名为 `index.html`。

### 3.2 仅栈 A 追加

```text
/
├── .env / .env.example           # 开发账号等（见 §10）
├── frontend/js/
│   ├── api.js                    # API 请求封装
│   └── config.js                 # 含 API_BASE_URL 解析（见 §6.4）
└── backend/
    ├── app/
    │   ├── main.py
    │   ├── models.py
    │   ├── database.py
    │   └── routers/
    ├── data/                     # SQLite 库文件
    ├── tile-cache/               # 瓦片缓存（地图项目）
    └── requirements.txt
```

### 3.3 仅栈 B 追加

```text
/
└── frontend/js/
    └── storage.js                # localStorage 统一封装（见 §6.5）
```

栈 B **不要**创建 `backend/`、`requirements.txt`、`.env`（无后端密钥时）、`api.js`。

## 4. 命名规范

| 类型               | 规范                                                  | 示例                                                       |
| ------------------ | ----------------------------------------------------- | ---------------------------------------------------------- |
| 目录               | kebab-case                                            | `frontend/css/pages/`、`backend/app/routers/`          |
| HTML 页面          | kebab-case，业务英文名；业务页禁止 `index.html` | `web/login.html`、`miniapp/todo.html` |
| 选端页 | 双端项目根目录固定 `index.html` | `index.html` → `web/` 或 `miniapp/` 登录页 |
| CSS / JS 文件      | kebab-case                                            | `layout.css`、`agent-workspace.js`                     |
| CSS 类名           | BEM                                                   | `agent-workspace__title`、`app-sidebar__item`          |
| Python 模块 / 文件 | snake_case                                            | `database.py`、`health.py`                             |
| Python 类          | PascalCase                                            | `TaskRecord`                                             |
| Python 函数 / 变量 | snake_case                                            | `get_health`、`init_db`                                |
| API 路径           | kebab-case，统一`/api` 前缀                         | `/api/health`、`/api/user-profile`（**仅栈 A**） |
| localStorage 键名  | 项目前缀 + kebab 或 snake，避免裸键污染               | `myapp:user-profile`（**仅栈 B**）                 |
| 常量（JS / Py）    | UPPER_SNAKE                                           | `API_BASE_URL`、`MAX_FILE_COUNT`                       |

## 5. 文件存放

| 内容                     | 位置                                      | 适用           | 说明                               |
| ------------------------ | ----------------------------------------- | -------------- | ---------------------------------- |
| 前端选端 / 单端入口 HTML | 项目根目录 | A / B | 双端用 `index.html`；单端可用业务名 `.html` |
| 各端业务 HTML | `web/`、`miniapp/`（英文端目录） | A / B | 与 `frontend/` 平级；勿堆根目录 |
| 骨架样式 / 脚本          | `layout.css`、`layout.js`、`nav.js` | A / B          | 入口只做壳                         |
| 业务页样式 / 脚本        | `css/pages/`、`js/pages/`             | A / B          | 文件名与 HTML 一致                 |
| 静态资源                 | `frontend/assets/`                      | A / B          | —                                 |
| 第三方库                 | `frontend/libs/`                        | A / B          | 必须本地化                         |
| API 封装                 | `frontend/js/api.js`                    | **仅 A** | —                                 |
| localStorage 封装        | `frontend/js/storage.js`                | **仅 B** | 见 §6.5                           |
| 后端路由 / 模型 / 库文件 | `backend/...`                           | **仅 A** | 库文件仅`backend/data/`          |
| 瓦片缓存                 | `backend/tile-cache/`                   | **仅 A** | 按瓦片源分目录                     |
| 文档                     | 根目录中文 Markdown                       | A / B          | —                                 |

**代码注释**：

- 用中文简述业务意图。

- 用途：工作交接与 Agent 检索。

## 6. 前端规范

### 6.1 骨架 vs 内容区

| 概念      | 范围                  | 约定                                              |
| --------- | --------------------- | ------------------------------------------------- |
| 骨架      | 侧栏 / 顶栏           | 仅本地联调展示；逻辑在`layout.js` / `nav.js`  |
| 内容区    | `#pageContent`      | 唯一挂载点；业务写在各页的 HTML / CSS / JS 三件套 |
| 入口 HTML | 根目录选端页或单端业务名 `.html` | 选端 / 壳承载；栈 A 保留 `?api=` 等查询参数 |

**多页约定**：

1. 业务页用英文文件名独立 HTML，放入 `web/` 或 `miniapp/`，不要全部平铺根目录。
2. 侧栏 / 导航链接由 `nav.js` 统一管理跳转。
3. 业务能力不要塞进 `layout.js` / `nav.js`。
4. 双端选端：根目录 `index.html` 点击端口跳转对应端登录页。

### 6.2 业务页模板

新建业务页必须按下列模板生成。`<head>` 与 `<body>` 脚本加载顺序**禁止调换**。

#### `<head>`

```html
<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>页面名称 · 系统名称</title>
    <link rel="icon" type="image/svg+xml" href="./frontend/assets/favicon.svg" />
    <!-- 1. CSS 变量（全局，必须最先） -->
    <link rel="stylesheet" href="./frontend/css/variables.css" />
    <!-- 2. 骨架样式 -->
    <link rel="stylesheet" href="./frontend/css/layout.css" />
    <!-- 3. 业务页样式 -->
    <link rel="stylesheet" href="./frontend/css/pages/xxx.css" />
  </head>
```

顺序（不可改）：`variables.css` → `layout.css` → `pages/xxx.css`。

页面若位于 `web/` 或 `miniapp/`，资源路径使用 `../frontend/...`（相对端目录回到公共资产）。

#### `<body>`

```html
  <body>
    <div class="admin-layout" id="adminLayout">
      <aside class="app-sidebar" id="appSidebar"><!-- 导航菜单 --></aside>
      <main class="app-main">
        <div class="app-main__content" id="pageContent">
          <div class="page-container">
            <div class="page-hd">
              <!-- 标题、筛选、操作栏；无可省略 -->
            </div>
            <div class="page-wrap">
              <!-- 表格、列表、表单、详情等 -->
            </div>
          </div>
        </div>
      </main>
    </div>

    <!-- 公共脚本（顺序不可改；按技术栈二选一） -->
    <!-- 栈 A：logger → icons → config → api → nav → layout → pages/xxx -->
    <!-- 栈 B：logger → icons → config → storage → nav → layout → pages/xxx -->
    <script src="./frontend/js/logger.js"></script>
    <script src="./frontend/js/icons.js"></script>
    <script src="./frontend/js/config.js"></script>
    <script src="./frontend/js/api.js"></script>
    <!-- 栈 B 将上一行换成：<script src="./frontend/js/storage.js"></script> -->
    <script src="./frontend/js/nav.js"></script>
    <script src="./frontend/js/layout.js"></script>
    <script src="./frontend/js/pages/xxx.js"></script>
  </body>
</html>
```

脚本顺序（不可改）：

- **栈 A**：`logger` → `icons` → `config` → `api` → `nav` → `layout` → `pages/xxx`
- **栈 B**：`logger` → `icons` → `config` → `storage` → `nav` → `layout` → `pages/xxx`

顺序错误会导致 `AppLog` / `AppIcons` / `API_BASE_URL`（栈 A）或 `AppStorage`（栈 B）等未定义。

#### 布局类

| 类名                | 职责                             |
| ------------------- | -------------------------------- |
| `.page-container` | 页面根容器，每页有且仅有一个     |
| `.page-hd`        | 标题、筛选、操作栏；简单页可省略 |
| `.page-wrap`      | 主体：表格、卡片、表单等         |

### 6.3 硬性约束

#### 6.3.1 禁止 CDN

- 不得通过 CDN 引用 JS、CSS、字体、图标等（jsDelivr、unpkg、bootcdn 等）。
- 静态资源放在项目目录内（`frontend/` 等），随项目交付。
- 第三方库本地化入仓库，或经后端静态目录提供。
- **例外**：必须引用外部地图瓦片、视频流等时，先征得用户同意；确认后写入项目 `AGENTS.md`（或项目说明），并在引用处注释原因。

#### 6.3.2 禁止内联样式

- 禁止 HTML `style="..."`。
- 样式写在 CSS 中，通过 class 引用。
- 动态样式优先 class 切换或 CSS 变量，不直接操作 `element.style`。
- **例外**：拖拽坐标、Canvas 尺寸等确需 JS 赋值时，先征求用户确认，并在代码处注释。

#### 6.3.3 禁止阴影

- 禁止 `box-shadow`、`text-shadow`、`drop-shadow`。
- **例外**（仍以克制为原则）：工作台 / 仪表盘、数据可视化（图表容器、图例浮层、ECharts/Canvas）、异型界面（拖拽面板、浮动画板等）。
- 卡片、按钮、输入框、表格、模态等常规 UI **一律无阴影**。

#### 6.3.4 表单布局

标签与输入框**必须同行**：标签右对齐，输入框紧随其后。禁止上下堆叠。

```text
❌ 账号          ✅ 账号  [请输入账号]
   [请输入账号]     密码  [请输入密码]
```

- 标签固定宽度或 `min-width`，右对齐；输入框占剩余空间。
- 标签与输入框间距统一（推荐 12px）；表单行间距统一（推荐 16px）。

#### 6.3.5 字号

| 用途                    | 字号 | 字重 |
| ----------------------- | ---- | ---- |
| 正文 / 常规 UI          | 14px | 400  |
| 小字 / 辅助说明（下限） | 12px | 400  |
| 小标题                  | 14px | 600  |
| 页面 / 区块标题         | 16px | 600  |

- 最小 12px，常规以 14px 为主。
- 禁止 11 / 13 / 15 / 17 等奇数或非规范字号。
- 优先使用 `variables.css` 中的 `--font-size-*`。

#### 6.3.6 圆角

| 用途                                 | 圆角                                                 |
| ------------------------------------ | ---------------------------------------------------- |
| 常规（卡片、按钮、输入框、菜单项等） | 6px（`--app-radius`）                              |
| 更小 / 中 / 更大                     | 2 / 4 / 8px（`--app-radius-sm` / `md` / `lg`） |

- 只用偶数：2 / 4 / 6 / 8。禁止 3 / 5 / 7 等奇数。
- 圆形头像等用 `50%`，不套用上表。
- 优先使用 `--app-radius*` 变量。

#### 6.3.7 图标

- 禁止 emoji、字符形「文字图标」（▣、◇、☰、➜ 等）。
- 一律 SVG 线框：`stroke-width="2"`，`stroke-linecap="round"`，`stroke-linejoin="round"`。
- 通过 `frontend/js/icons.js`（`window.AppIcons`）引用；页面用 `data-icon="name"` 占位，由脚本注入。
- 新增图标先写入 `AppIcons`，禁止页面内散落临时图标。

#### 6.3.8 全局日志

- 使用 `frontend/js/logger.js`（`window.AppLog`）。
- 常用：`AppLog.info/warn/error(scope, message, detail)`；`AppLog.dump()` 查看缓冲。
- 已自动监听 `fetch` / 全局错误。业务排错优先 `AppLog`，避免无标签的 `console.log`。

#### 6.3.9 禁止「演示感」文案

界面、提示、空态、按钮、报表标题等**一律禁止**：

「演示」「模拟」「Demo」「demo」「样例」「测试数据」「假数据」等。

联调说明写在规范、`AGENTS.md` 或代码注释中，**不要写进页面可见文案**。

#### 6.3.10 禁止浏览器默认弹窗与悬停 tip

| 禁止                                             | 替代                       |
| ------------------------------------------------ | -------------------------- |
| `alert` / `confirm` / `prompt`             | 页内模态、轻提示、行内校验 |
| `showOpenFilePicker` / `showDirectoryPicker` | 隐藏`input[type=file]`   |
| HTML`title` 悬停、移入才出现的 tip / tooltip   | 文案、图标或常显说明       |

**允许**：`<input type="file">` 系统文件选择器；需求明确要求的 `showSaveFilePicker`。

**例外**：需求明确要求某处悬停时才可加 tip，并写入对应约定；禁止自行添加。

无障碍可用 `aria-label`（不依赖悬停）。`document.title`、iframe 无障碍 `title` 不受本条约束。

### 6.4 前端 API 地址（`config.js` / `?api=`）— 仅栈 A

栈 B **跳过本小节**。

- **唯一入口**：`API_BASE_URL` 只在 `frontend/js/config.js` 中定义；业务页与 `api.js` 一律引用它，**禁止**在页面脚本里写死 `http://127.0.0.1:8000` 等地址。
- **解析优先级**（高 → 低）：

  1. URL 查询参数 `?api=`（一键启动打开浏览器时写入，适配动态端口）
  2. `config.js` 中的开发默认值（仅作本地兜底）
  3. 相对路径同源（若前后端同域部署）
- **一键启动**：打开入口页时必须带上当前后端地址，例如 `?api=http://127.0.0.1:8001`；`config.js` 读取后写入 `API_BASE_URL`，并尽量在跳转时保留该参数（与 `?username=` / `?password=` 一并处理）。
- **手动联调**：可用 Live Server 打开页面时自行追加 `?api=`；不要改代码写死端口。
- **交付 / 宿主环境**：按部署方式改 `config.js` 默认值或改由宿主注入；仍禁止把本机调试端口写进交付代码。

### 6.5 localStorage 约定 — 仅栈 B

栈 A **一般不使用**本小节（服务端数据走 API / SQLite）。

- **唯一入口**：业务页禁止直接调用 `localStorage.setItem/getItem`；统一经 `frontend/js/storage.js`（建议挂 `window.AppStorage`）读写。
- **键名**：必须带项目前缀，如 `myapp:settings`、`myapp:draft-list`，禁止无前缀短键（避免与其它系统页冲突）。
- **值**：对象 / 数组一律 `JSON.stringify` / `JSON.parse`；`AppStorage` 内做好 try/catch，解析失败时回落默认值并 `AppLog.warn`。
- **容量与清理**：大数据（如图片 Base64、巨型列表）慎用；提供按前缀清空的调试方法（如 `AppStorage.clearPrefix()`），勿在对客界面暴露「清空演示数据」类文案（见 §6.3.9）。
- **无后端**：不创建 `api.js`、不请求 `/api`；需要「假登录」时仅用内存或 `AppStorage` 存会话标记，仍遵守禁止演示感文案。

## 7. 后端与 API（仅栈 A）

> **栈 B 整章跳过。** 不要创建 `backend/`，不要引入 FastAPI / SQLite。

### 7.1 基本约定

| 约定      | 要求                                                                 |
| --------- | -------------------------------------------------------------------- |
| 前缀      | 全部`/api`                                                         |
| 路径命名  | kebab-case，如`/api/user-profile`                                  |
| HTTP 方法 | 查询 GET；创建 POST；更新 PUT/PATCH；删除 DELETE                     |
| 响应体    | JSON：`{ code, data, message }`（见 §7.2）                        |
| 路由组织  | 按业务拆`routers/*.py`，在 `main.py` 挂载                        |
| 静态资源  | 需本地化的第三方库可通过后端静态目录提供；禁止前端 CDN（见 §6.3.1） |

### 7.2 响应码约定

统一信封：

```json
{ "code": 0, "data": {}, "message": "ok" }
```

| `code` | 含义               | HTTP 状态（建议）   | `data`                                     |
| -------- | ------------------ | ------------------- | -------------------------------------------- |
| `0`    | 成功               | 200（创建可用 201） | 业务数据；无数据时用`null` 或 `{}`       |
| `400`  | 参数 / 校验错误    | 400                 | 可选，细节放`message` 或 `data`          |
| `401`  | 未登录 / 凭证无效  | 401                 | 通常`null`                                 |
| `403`  | 已登录但无权限     | 403                 | 通常`null`                                 |
| `404`  | 资源不存在         | 404                 | 通常`null`                                 |
| `409`  | 冲突（如重复创建） | 409                 | 可选                                         |
| `500`  | 未预期服务端错误   | 500                 | 通常`null`；细节只写日志，不把堆栈回给前端 |

约定：

- **业务成败看 `code`**：`code === 0` 为成功；前端 `api.js` 统一判断，页面不各自解析 HTTP 再猜。
- **HTTP 与 `code` 对齐**：能映射时保持一致（如上表）；网络层失败（断网、5xx 无 JSON）由 `api.js` 转成统一错误对象再抛给页面。
- **`message`**：给人看的短中文；成功可用 `"ok"`；失败必须可读，禁止空字符串。
- **扩展码**：确需更细的业务码时，用 `4xxxx` / `5xxxx` 段，并在项目 `AGENTS.md` 登记；通用成功仍固定为 `0`。

### 7.3 库表变更（SQLite）

- 模型以 `backend/app/models.py` 为唯一结构来源；库文件只落在 `backend/data/`。
- **启动建表**：应用启动时允许 `Base.metadata.create_all()`，仅用于**新建库 / 新表**，**不会**自动改已有表结构。
- **变更策略**（按场景选，改前先跟用户确认是否可丢本地数据）：

| 场景                    | 做法                                                                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 本地开发、可清空数据    | 删除`backend/data/` 下对应 `.db` 后重启，由 `create_all` 重建                                                                        |
| 需保留数据              | 编写一次性迁移（SQL 或脚本）：`ALTER TABLE` / 建新表迁数据 / 删旧表；放入 `backend/app/migrations/` 或等价目录，启动时按版本号顺序执行 |
| 仅加可空列 / 无依赖新表 | 可走迁移脚本追加；禁止手改生产库却不留脚本                                                                                                 |

- **版本记录**：有迁移时，库内维护简单 `schema_version`（表或键值），避免重复执行。
- **禁止**：在已有库上指望只改 `models.py` 就自动变列；禁止把开发用 `.db` 当交付物提交（见 §10）。

### 11.3.1 为什么 Agent「会记得」更新 AGENTS.md（必写写法）

Agent **没有跨对话记忆**。会不会自觉更新 `AGENTS.md`，不取决于「做着做着想不想起」，而取决于：**这条义务有没有写进会被自动注入上下文的文件**。

| 机制                                             | 作用                                       |
| ------------------------------------------------ | ------------------------------------------ |
| 项目根`AGENTS.md`                              | Cursor 当作 Always 规则注入每次 Agent 对话 |
| `.cursor/rules/*.mdc`（`alwaysApply: true`） | 同上，可拆成短规则                         |
| User Rules（设置 → Rules）                      | 跨项目个人偏好                             |

**反例（会忘）**：只口头说过「改完要同步手册」，或只写在聊天记录里 → 新对话 / 长对话后失效。
**正例（不忘）**：写进 `AGENTS.md` 文首，且用「漏更 = 未完成」这种可验收措辞。

每个项目 `AGENTS.md` **文首必须具备**：

```markdown
> **维护约定：凡改动目录结构、路由、入口、样式主题、模块依赖或跨模块约定，须在同一次工作中同步更新本文件，无需用户另行提醒。**

最后核对：YYYY-MM-DD · 〈一句话写本次改了什么〉
```

文末保留「更新本文件的检查清单」勾选项；Agent 收工自检：**代码改完 ≠ 完成，手册「最后核对」未动 = 未完成**。
（具体模块名、业务路径写进各项目 `AGENTS.md` 正文条目，**不要**在文首堆业务点名。）

### 11.4 文件编辑（Trae CN）

Trae CN 编辑大文件时，理解失败可能整文件删除后逐行重写；输出过长会被截断。为避免丢代码：

1. **先建骨架**：新文件先写入完整空壳，保证结构存在。
2. **分段注入**：后续用精准片段替换，每次只改目标段落。
3. **禁止全量重写**：不得用整文件覆盖更新已有代码。

在 Cursor 等支持可靠局部编辑的环境中，仍优先小范围修改，避免无必要的整文件重写。
