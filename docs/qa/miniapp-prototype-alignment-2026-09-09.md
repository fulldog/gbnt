# 小程序原型对照与样式调整

日期：2026-09-09。范围为 `apps/miniapp` 的 10 个正式页面及共享组件；基准为 `prototypes/static-demo/miniapp` 当前 HTML 的实际渲染。原型目录保持只读。

本次已经修正主要页面的视觉结构和基础样式。原型与正式版还有表单版本、字段和业务流程差异，详见文末；这些差异不能用 CSS 修复，也没有通过隐藏未实现的功能来宣称全流程一致。

## 差异来源

1. **页面结构不一致。** 原型的待办是“左头像、右侧内容”的信息流，正式版把姓名、组织、时间和照片拆成多排独立区域。原型巡查是紧凑行表单，正式版增加了蓝色步骤大标题和嵌套卡片。原型个人中心是白底，正式版使用渐变头部和分组卡片。
2. **未区分原型当前样式与历史样式。** `mobile.css` 仍保留 `.m-hd--profile` 等旧渐变规则，当前 `mine.html` 实际使用 `.m-mine__identity` 等白底样式。本次以实际 DOM 和计算样式为准。
3. **尺寸口径混用。** 原型正文通常为 14px、辅助信息为 12px；正式页面混用 rpx、14px、16px，圆角还包含 12px、16px 等较大值，同一类组件在不同页面不一致。
4. **共享组件重复。** 待办和我的清单各自实现了一套卡片，导致头像、图片排列、间距和状态样式逐渐分离。
5. **正式扩展信息挤占首屏。** 详情页将业务编号、完整时间、责任人和轮次等全部放在基本信息里，排查清单被挤到下方。现将这些内容放进可展开的“补充信息”，原数据仍可查看。
6. **遗漏设备外壳生成的标题。** 待办顶部的“农田专项整治”由 `device-shell.js` 根据 `data-mp-title` 插入；正式自定义导航现已补齐该标题。筛选栏原先混用文字箭头和 CSS 箭头，现统一使用与原型相同路径的 14px 图标。

## 视觉基准

| 项目 | 原型基准 | 正式实现 |
| --- | --- | --- |
| 主色 | `#015cbb` | 统一颜色 token |
| 主色浅底 | `#e8f1fb` | 卡片头像、选中态和状态标记共用 |
| 正文 / 辅助色 | `#152033` / `#6b7a90` | 统一两套旧前缀的实际值 |
| 字体 | 思源黑体、Noto Sans、苹方、微软雅黑 | 统一字体栈，使用设备可用字体，不加载远程字体 |
| 通用字号 | 正文 14px；辅助 12px；普通标题 16px | 以页面和组件语义落地，保留原型特殊字号 |
| 特殊字号 | 登录标题 20px；个人姓名/统计 22px；巡查题目和签名标题 24px | 保留这些例外，避免所有文字机械缩成同一字号 |
| 圆角 | 常用 6px / 8px；小标签 4px | 收敛到统一 token |
| 一级页面顶部 | 透明状态栏和胶囊区；待办左侧显示“农田专项整治” | 使用自定义导航；按状态栏及胶囊实际位置留白，并为待办显示 16px、600 字重的标题 |
| 二级页面顶部 | 标题及返回入口 | 保留微信原生导航 |
| 页面分隔 | 白底，10px 浅灰分区 | 详情按原型分区 |

## 字符图标专项排查

在登录滑块、筛选栏、设施类型和定位栏已修正的基础上，扫描了正式小程序全部 28 个 Vue 文件及相关 TypeScript、SCSS。另发现 8 个文件、17 处以字符代替图标的用法，现已替换为本地 SVG；计数按模板中的图标位置统计，展开/收起的两个方向合计一处。

| 页面或组件 | 处数 | 原用法 | 替换结果 |
| --- | ---: | --- | --- |
| 巡查题目 `QuizCard` | 2 | 是、否选中标记 `✓` | 24px 圆形容器内使用 18px 白色勾选图标 |
| 巡查照片 `PhotoPicker` | 2 | 删除 `×`、添加 `＋` | 关闭及加号 SVG；删除按钮保持 44px 点击区域 |
| 详情整改 `RectifyForm` | 2 | 删除 `×`、添加 `＋` | 复用关闭图标及蓝色加号；保留禁用态与增删事件 |
| 待办 | 2 | 清空搜索 `×`、空状态 `✓` | 20px 关闭图标、26px 蓝色勾选图标 |
| 我的 | 3 | 修改密码、用户协议、隐私政策入口 `›` | 原型同款 16px 右箭头，颜色为 `#c0c6ce` |
| 详情 | 3 | 展开/收起 `⌄/⌃`、定位 `●`、查看地图 `›` | 14px 可旋转箭头、18px 图钉、14px 右箭头 |
| 地图 | 1 | 重新定位 `◎`，加载中 `…` | 20px 定位图标，定位中显示 CSS 加载动画 |
| 我的清单 | 2 | 加载失败 `!`、空状态 `□` | 28px 警示及列表图标 |

图标使用固定宽高及 `flex: none`，避免在长文字旁被压缩。勾选、关闭、加号、列表、箭头和图钉复用原型的 SVG 路径；正式扩展的地图定位、加载失败图标使用相同的 24px 画布、2px 圆角描边规则。

复扫未再发现上述字符、字符实体或私有区字体图标。普通标点、必填星号、头像文字以及 CSS 边框绘制的图形不属于字体字符图标。全部 16 个被引用的 SVG 已通过格式检查，且源码与生产包内的对应文件逐一一致。

本轮在微信开发者工具中确认了待办搜索清除、空状态图标及清除后恢复列表。随后截图停留在旧待办画面，而当前页面路径和无障碍树已切换到我的页，重新选择窗口后仍不一致，因此本轮其余图标只计入源码、类型检查、测试和构建验证，未宣称已完成逐项视觉验收。没有为验收覆盖巡查草稿、调用相机/定位或提交业务记录。

## 保留的正式能力与业务差异

- **年度筛选：** 按原型及用户要求，待办移除年度筛选入口，保留类型、行政区划、状态三项；记录自身的年度信息仍正常展示。
- **真实摘要与身份信息：** 正式卡片显示真实异常说明、设施类型、年度和组织路径。不同长度的数据会导致卡片高度与演示数据不同。
- **补充信息：** 详情中的状态、业务编号、完整排查时间、计划日期、上报人、整改责任人、轮次、负责人及联系电话均保留在展开区域。
- **正式表单仍使用当前提交结构：** 原型有机井独立全景照片、道路损坏等新版题目；当前正式巡查页使用 `domain/issues/definitions.ts`、`form.ts` 和 `mapper.ts` 的既有表单。共享契约和读取端已能识别部分 `schema_version=2` 信息，但这不等于正式上报流程已经完整切换。本次没有迁移题目、草稿和提交版本；要让整个业务流程也与原型一致，需要单独完成表单版本迁移及端到端校验。
- **正式定位与上传：** 原型定位超时会使用演示地址。正式版继续要求真实定位和既有拍照/上传规则，不把演示地址作为真实位置。
- **定位栏状态：** 尚无有效坐标时只显示“获取定位”按钮；成功选择位置后显示原型同款图钉、可补充的地址和刷新图标。获取期间禁用重复点击；取消或失败保留原状态和已有位置。
- **定位必填范围：** 小程序首步和最终提交均要求非空地址及有效经纬度，照片水印使用该坐标。后端创建接口当前仅强制地址非空，尚未对经纬度做相同的有效性校验；本次未更改必填规则或后端接口。
- **整改：** 保留异常项选择、分批提交、草稿、上传以及历史轮次读取。原型单一整改输入框不直接替换正式逐项提交模型。
- **分享：** 待办、巡查和详情的好友分享、朋友圈分享回调保留；详情仍携带记录 ID。
