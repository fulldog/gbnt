# 小程序 UI 与数据修复记录

日期：2026-09-05。范围为 `apps/miniapp` 的 UI、异常数据与弱网恢复，并同步必须调整的后端契约和管理后台轮次展示。原型只作参考，未修改；未修改接口文档、权限规则或执行 Git 提交。

## 已实现

- 登录：复用原型背景、Logo 和图标，压缩图片；恢复页面滚动、键盘避让与安全区；原生 TabBar 补齐图标。
- 卡片与详情：展示真实上报人、责任人和组织信息，补问题摘要。服务端批量补充关联名称，不逐行查询。展示字段缺失明确提示，不编造姓名、数值或坐标。
- 列表：刷新失败保留旧列表及总数并标记未更新；重试原来的刷新或翻页请求；返回列表重新加载，忽略过时响应。
- 接口与会话：分页、题单、状态、身份、统计及上传结果增加运行时校验；关键数据损坏明确报错，不能默认为正常。旧账号的响应、401 和续期头不能污染新会话。
- 日期：按北京时间显示时间与计划标签，页面重新显示或跨日时更新，非法日期不出现 `NaN`。
- 上报：按后端定义逐题填写，正常题也开放选填说明和照片；机井数量校验非负整数；照片选择/上传未完成时阻止换题和提交。
- 照片：逐张记录上传成功结果，同批部分失败不丢已成功项；失败可重试或移除，离开页面后停止回填；取证重试保留原拍摄时间。切换为机井出水取证时清理普通来源照片，旧草稿缺少拍摄来源或时间需重新拍摄。
- 定位与权限：缺少有效地址/坐标不生成 `(0, 0)` 水印；取消不报错误，拒绝定位或相机权限提供中文说明和设置入口。
- 图片显示：加载状态、远端失败时的本地预览和失败点击重试；保留原始附件地址，避免破坏签名 URL；微信端使用真实重建节点及事件标记隔离旧加载回调。
- 草稿：上报自动保存并如实报告保存/清理失败；按当前正式题序恢复；页面固定草稿所属用户。整改说明按用户、记录和轮次保存，临时整改照片不承诺跨页面有效。
- 整改：保留所有历史记录，但只按当前轮次判断完成；管理后台、小程序同步显示轮次并提交 `expected_round`。轮次过期提示刷新，避免旧页面取证写入新一轮。

Vue、UI/UX 与 Vitest 技能用于约束异步状态隔离、失败恢复、触控区域及对应回归用例；视觉仍以原型和实际后端字段为准。

## 部署前必须处理

1. 新增 `issues.rectify_round` 和 `issue_rectify_records.round`，默认值均为 `0`（界面显示第 1 轮）。需先备份数据库、确认现有历史数据，再迁移结构并同步部署后端、小程序和后台。
2. 仓库迁移随后端启动执行，无独立 migration-only 命令。持久化环境必须明确配置 `server.mode: release`、`migrate.enabled: true`、`migrate.seed: false`；检查迁移完成与字段后关闭迁移开关。release 迁移还会同步 API 注册目录，并非只执行两个字段的 SQL。
3. **禁止以 debug/dev 模式开启迁移进行升级：现有逻辑会删除当前数据库全部表。** 不要使用仅加在 `systemctl restart` 命令前的环境变量来假定已改变服务配置，应确认服务实际读取的私有 YAML 或 unit 环境。
4. 升级前已经“重新整改”的历史记录无法仅靠旧数据自动还原准确轮次，应检查并人工确认；不能把所有旧记录伪造为新一轮。
5. 旧客户端可以省略 `expected_round`，但不具备过期轮次保护；仅前端兼容旧服务也不能修复服务端历史累计逻辑。
