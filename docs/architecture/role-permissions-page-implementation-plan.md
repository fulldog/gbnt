原型是只读视觉和交互参考。保留其手工填写英文角色ID的语义，描述性角色名称按“创建时自动命名”要求生成。

## 3. 页面调整清单

### 3.1 查询区、工具栏与布局

- 移除页内重复的大标题和“API 数字 ID”技术说明；导航面包屑继续显示“角色权限”。
- 查询区拆成“角色名称”“角色ID”，提供“重置”“查询”，支持回车查询。
- 角色名称模糊匹配；角色ID按英文标识精确匹配、不区分大小写。非法ID显示校验提示。
- 输入条件与已应用条件分开，点击查询后应用；查询、重置和切换每页条数均回到第一页。
- 表格工具栏标题为“角色管理”，提供“新增角色”、隐藏/显示查询、刷新、全屏、列设置。
- 表格填满剩余内容高度，内部滚动，底部分页保持可见；窄屏保留横向滚动。
- 默认每页10条。当前接口返回完整角色列表，本期在前端完成筛选和分页。
- 页面内按创建时间、ID倒序稳定展示，新增成功后回到第一页；不改变角色列表接口供其他页面使用时的契约。
- 复用现有 `QueryPanel`、`TableToolbar` 和 `data-page/data-card/data-table/data-pagination` 样式。
- 对齐原型的10px区域间距、44px表格行高、浅灰表头、边框、内边距和文本对齐；适配时以实际渲染复核。
- 查询区没有额外条件时不添加无实际内容的“展开”按钮。

### 3.2 表格字段

| 顺序 | 列名 | 数据/展示规则 |
| --- | --- | --- |
| 1 | 序号 | 展示编号，不使用数据库ID；对齐当前原型，按过滤后总数减分页偏移和行索引计算 |
| 2 | 角色名称 | `name`；新角色自动命名，历史角色展示已有名称 |
| 3 | 角色ID | `code`；手工填写、唯一，普通角色可修改，不展示内部数字主键 |
| 4 | 备注 | `desc`；长文本省略并可查看完整内容 |
| 5 | 创建时间 | `created_at`；按原型显示到秒，不改变其他页面现有时间格式 |
| 6 | 状态 | `status`；使用开关，启用为1、停用为0 |
| 7 | 操作 | 仅“修改”“删除”，固定右侧，宽度约140px |

状态开关请求期间显示行级加载状态，失败后恢复原值；更新状态时只提交状态字段，避免用列表旧值覆盖备注或名称。

操作按当前用户权限显示或禁用。内置管理员角色继续受后端保护，其修改、删除和状态切换禁用并提供原因提示；不放宽系统角色保护规则。

### 3.3 新增和修改弹窗

新增和修改使用同一套表单组件，结构为“角色ID、角色备注、授权、取消/保存”。角色名称作为ID下方的只读预览展示，不提供手工名称输入。

- 新增：英文角色ID必填；选择授权后即时预览角色名称；备注人工填写，默认启用。
- 角色ID以英文字母开头，支持英文、数字、下划线和短横线，最多64位；保存时去除首尾空格、统一小写。前端校验格式，后端校验格式并通过数据库唯一约束防止并发重号；删除后的标识仍保留。
- 修改：回显英文角色ID、已存名称、备注和完整授权，可修改普通角色的英文ID；修改权限时保留已存名称。内部数字主键和人员、权限关联不变。
- 弹窗保持原型紧凑风格：桌面最大640px宽、80dvh高，标签在左；正文滚动，标题和底部按钮固定。窄屏标签上下排列，避免横向溢出。
- 授权区域按“顶级模块 → 页面 → 操作”展示，具备展开/收起、全选、取消全选和半选状态。
- 操作使用“查、增、改、删、导入、导出”等业务文案；只显示真实API目录中存在的可授权操作。
- 一个业务操作关联多条API时，统一勾选该组；历史部分授权显示半选，未操作的组保留原始选择。
- 移除列表的独立“授权/查看权限”按钮和独立授权抽屉，授权入口统一进入修改弹窗。
- 目录加载失败时提供重试；已有权限尚未加载完成时禁止保存，避免误清空。
- 保存期间防重复提交；失败保留输入和勾选，成功后关闭弹窗并刷新列表。
- 角色信息和授权一次保存，不能出现两次独立请求导致的部分成功。

## 4. 自动命名与授权规则

本次实施采用以下完整默认规则。

### 4.1 命名映射

| 选中的业务权限 | 顶级职责 | 生成名称 |
| --- | --- | --- |
| 组织架构、工作人员、角色权限、操作日志中的任意页面 | 系统配置 | 系统配置员 |
| 街道台账、街道排查汇总中的任意页面 | 汇总管理 | 汇总管理员 |
| 专项整改中的任意操作 | 专项整改 | 专项整改员 |
| 同一顶级职责下多页面、多操作 | 去重后的一项职责 | 不重复拼接名称 |
| 跨多个顶级职责 | 按菜单固定顺序排列 | 例如“汇总管理员、系统配置员” |
| 只有工作台查看权限 | 基础查看职责 | 工作台查看员 |
| 没有任何业务或工作台权限 | 无业务职责 | 未分配职责 |

只要有该顶级模块下的有效授权即可参与命名，不要求取得顶级模块的全部操作。名称不表示拥有该模块全部权限，授权判断继续以实际权限为准。

名称允许重复，由角色ID区分。不会因名称生成“系统配置员”而自动获得更多权限，也不会按名称查找并合并不同角色。

### 4.2 基础权限与目录

当前“管理后台登录”也是单独的RBAC权限，原型页面没有呈现这一后端约束。新弹窗增加可见的基础权限项“允许登录管理后台”，不将其计入职责命名。

建议新建默认勾选“允许登录管理后台”和原型默认的“工作台查看”，两项均明确展示且可取消。无后台登录权限时应说明该角色不能登录管理后台；已有角色回显时不自动补授这两项。

空权限数组可明确保存为“未分配职责”，提示其未获管理后台操作授权，不在保存时暗中补授权限。这也保留现有仅供小程序使用的角色场景；当前小程序业务接口使用JWT，不在本次页面调整中增加小程序RBAC。

权限目录是配置来源：不在前端硬编码数字API ID。未展示、停用或目录外的历史授权不能因编辑备注就丢失；后端保留未触碰的历史关联，拒绝新增不存在、停用或不可授权的ID。

### 4.3 前后端名称一致

后端负责最终命名。建议由后端对API目录补充顶级职责元数据，管理端使用相同元数据做分组和名称预览，避免两份独立映射漂移。

`GET /api/sys/apis` 保持现有数组结构，在业务API条目上补充可选的顶级组标识、组名称和角色称谓字段；基础权限不提供业务称谓。目录另带 `role_code_supported: true`，新页面据此确认后端不会忽略英文角色ID。这些元数据由服务层生成，不落库。

前端和后端共用同一组命名场景做契约校验；最终展示以创建接口返回的名称为准。目录中出现未配置顶级职责的新业务模块时，应展示明确的配置提示，不静默遗漏已选职责。

## 5. 后端和API实施方案

### 5.1 数据结构

新增 `sys_roles.code`（可空 `varchar(64)`，独立唯一索引），继续复用 `id/name/desc/status` 和 `sys_role_apis`。使用可空字段支持已有多行数据的增量建索引；业务创建保证写入有效标识。

迁移在现有 `AutoMigrate` 后执行，仅回填缺失code：内置管理员为 `admin`，其他历史角色为 `role-数字主键`，遇冲突追加后缀。包含软删除记录并保留其标识；重复执行不更改已有标识。不批量重命名历史角色，不改主键、时间、状态、人员与权限关联。

### 5.2 接口调整

| 接口 | 新页面使用方式 | 兼容规则 |
| --- | --- | --- |
| `GET /api/sys/roles` | 列表、查询、分页及用户角色选项的数据源 | 保持现有响应数组，增加 `code`；`id`语义不变 |
| `GET /api/sys/apis` | 授权目录、顶级职责元数据和英文角色ID能力标记 | 保持数组结构，新增字段兼容旧客户端 |
| `POST /api/sys/roles` | 提交 `code`、`desc`、`api_ids`，后端生成名称，默认启用，事务创建角色和权限 | 旧客户端省略code时生成 `role-UUID`；显式空code拒绝。区分未传 `api_ids` 与空数组；未传时保留旧名称创建行为，新页面始终传数组 |
| `PUT /api/sys/roles/:id` | 修改弹窗提交 `code`、`desc`、`api_ids`；状态开关只提交 `status` | 路径仍使用内部数字主键。只更新明确传入字段；未传权限保持不变，空数组清空。兼容旧客户端传入名称 |
| `GET /api/sys/roles/:id/apis` | 修改时读取原始授权ID；管理员保留 `"*"` 响应 | 保持既有特殊值处理 |
| `PUT /api/sys/roles/:id/apis` | 既有独立调用继续可用，复用权限校验和事务服务 | 本次移除的是独立UI入口，不删除兼容接口 |
| `DELETE /api/sys/roles/:id` | 删除角色 | 保留管理员不可删、已被人员使用不可删的约束 |

正式前端分别定义创建、更新入参，不再让新增和部分更新共用要求所有字段必填的 `RoleInput`。继续使用统一响应信封；管理端方法留在管理端业务API文件，平台无关类型按现有边界维护。

### 5.3 保存一致性和鉴权

1. 校验角色存在、可修改，校验英文角色ID格式及唯一性、备注长度、状态枚举和权限ID格式。
2. 校验权限目录、去重ID。新增授权只接受有效可授权ID；修改时保留未触碰的历史关联。
3. 组合创建同时校验现有“新增角色”和“设置角色权限”所需授权，不能因接口合并降低原有授权门槛。组合修改沿用修改和授权的现有门槛，前后端判断一致。
4. 在同一事务中写角色及权限。任何一步失败均回滚，不返回创建或更新成功。
5. 提交成功后清理该角色的权限缓存。修改当前登录用户所属角色时刷新当前身份与权限；若新权限不允许继续访问当前页，按既有登录/路由规则处理。
6. 处理重复点击、请求失败和切换弹窗造成的迟到响应；保存失败不能被列表刷新成功掩盖。

## 6. 人员管理的必要联动

自动生成的描述性名称可能相同，本次只处理由此直接引起的角色识别问题。

- 新增/修改人员：角色选择框显示“名称（角色ID：英文标识）”；提交值仍为内部数字 `role_id`。
- 人员导出：“角色ID”列使用文本英文code，保留“角色名称”列；无绑定或关联已缺失的历史人员保持空角色列，不阻塞整批导出。
- 人员导入：角色ID优先按英文code识别；非法或不存在时报错，不能回退匹配名称。
- 兼容旧文件：保留纯数字主键ID导入；没有角色ID时按唯一名称精确匹配，名称不唯一时提示填写角色ID，不任意选择第一个角色。
- 同时填写ID与名称但两者不一致时提示修正，避免录入者选错角色。
- 角色字段至少提供ID或名称之一，其余人员校验和整批事务规则保持原有行为。
- 管理端导入/导出API方法、相关文件格式说明及测试同步更新；不扩展其他人员功能。

## 8. 验收标准

### 页面与核心流程

- 表格默认按约定显示7列，角色名称与ID独立，备注取 `desc`；操作栏没有“授权、查看权限、启用/停用”等额外操作。
- 查询和重置生效，分页及条数切换正确，删掉最后一页最后一条后页码自动回退。
- 新增时可以勾选完整授权，名称即时预览；勾选系统配置下不同子页面均生成“系统配置员”。
- 同顶级去重、跨顶级排序、只有基础权限、空权限均按命名规则处理。
- 新增后可立即读取到所选授权，取消弹窗不创建角色，不产生半成品角色。
- 修改正确回显权限半选状态；仅改备注不影响名称及权限，改权限不重命名。
- 状态修改不覆盖其他字段；内置管理员保护、被人员引用的角色不可删除仍生效。
- 英文ID与内部数字主键分离；重复ID创建/修改均失败并回滚，修改英文ID不改变人员和授权关联；迁移幂等、保留历史字段。
- 同名角色可借助ID区分，人员选择和导入不会分配到错误角色。

### 权限和失败路径

- 目录加载失败、已有权限读取失败、保存失败时，操作状态正确，输入可恢复，不误清空授权。
- 模拟权限写入失败，验证角色新增/更新整体回滚。
- 验证显式空数组与未传字段的区别；旧API入参和历史角色仍可读取及使用。
- 权限ID非法、停用、目录外新增请求被拒绝；历史未触碰的权限不被静默删除。
- 基础后台登录权限能明确勾选并正确生效；没有授予某页面或操作时，实际后端访问仍受限。
- 具备新增但不具备授权权限的账号不能通过组合接口获得原本不允许的授权能力。
- 修改当前用户所属角色后，前端展示及后端权限缓存一致。
