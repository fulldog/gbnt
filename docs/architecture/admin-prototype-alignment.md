## 修正基准

“按照后端字段”约束数据来源、业务枚举和统计口径，不授权删减原型的核心信息结构。此前把工作台简化为类型分布、把两张报表简化为 `type/total/pending/done` 普通列表，不满足原型中的页面要求。

## 页面结构

- 工作台：5 个统计卡；整改趋势与类型排行并排；近七天、近一个月、近半年、全部切换；待办表保留类型、编号、行政区划、整改人、计划完成、倒计时、状态，并支持分页。
- 街道台账：16 列、整行报表标题、三级分组表头，建设年份/街道/新村按连续层级跨行合并；包含机井、桥涵闸、道路、林网、变压器、签字和电话；保留盖章签字脚注。
- 街道排查汇总：22 个逻辑列、四层表头；左侧街道、新村/社区、自然村、全面排查完成固定；设施排查、问题/整改数量、联系人和签章分组展示。
- 两张报表均使用白底细网格、表内横向滚动、刷新、全屏和导出；Element Plus 保留在筛选及操作控件，复杂合并结构使用语义化原生 `table`。
- 数据加载失败、无数据、候选加载失败均分别展示；刷新或换筛选不保留旧数据，不把异常显示成全零。

## 数据与接口边界

保留原有聚合接口以兼容已有调用方，新增管理端报表接口及专用 TypeScript 契约，不放入两端共享业务类型：

- `GET /api/workbench/trend`：按北京时间日/月/年聚合上报与当前完成记录。完成时间来自当前整改轮次的有效整改记录，缺少完成记录的 `done` 不使用上报时间补齐。
- `GET /api/workbench/todos`：未完成的 `new/pending` 记录，计划到期优先，返回独立分页、名称与自然日倒计时。
- `GET /api/ledger/street/report`：按建设年度和落点组织分组，服务端解析组织祖先，返回已采集的道路长度、林网移交及现有株数。
- `GET /api/ledger/survey/report`：按落点组织分组，依据当前保存的排查清单识别异常；原本正常且直接 `done` 的记录不算整改完成。类型清单缺失或无效时返回未知，不降级为 0。

新接口沿用对应页面的查看权限；不开放新编辑权限，不改变原有数据授权范围。服务部署后需同步既有 API 目录；后端按模块/动作判权，已有对应模块查看权限的角色可访问，无需逐项重新授权。

## 不能虚构的字段

当前组织只有 `root/district/street/village`，没有自然村层级。没有资产唯一标识和完整资产基表，不能把上报次数当作现有设施数或已排查设施总数；也没有村级全面排查确认、报表联系人任命、签字盖章字段。

因此这些字段返回 `null`、页面显示 `—` 并说明“待采集/无法判定”，不等于 0。林网株数、道路长度只是筛选内上报记录字段的合计，尚未按资产去重。问题/整改数量也是记录口径、当前快照，不是历史事件累计。原型中的“机井移交数 = 记录数 + 2”等演示算法不迁移。新报表查询起止日期按北京时间解析为 `time.Time`，包含起日零点、排除终日次日零点，与工作台时间语义一致；未改现有 DSN。

原型移交数量支持本地覆盖，但正式后端尚无对应存储和并发校验，本次展示不会出现无真实保存能力的编辑按钮。若需要编辑，应另行确定资产/村级台账模型、保存接口、审计和编辑权限。

## 导出

当前显示的报表导出为 Excel 2003 SpreadsheetML `.xml`，保留标题、行列合并、网格和脚注，可用 Excel/WPS 打开后另存为 `.xlsx`；不会把 XML 伪装成 `.xlsx`。所有文本按字符串单元格导出，避免电话前导零丢失或把内容当公式。导出不是全量资产报表生成，不补充页面以外的未知字段。
